# 官网只读接口 v1

实现：`backend/app.py`。本地联调根地址 <http://127.0.0.1:9000/>；公网根地址为 <https://1531026871-73sj75z34t.ap-guangzhou.tencentscf.com>，实际版本见 [整体验收](../2026-11-12-整体验收.md)。

| 请求 | 含义 | 兼容旧地址 |
| --- | --- | --- |
| GET /api/v1/products | 产品数组 | /products |
| GET /api/v1/site-content | 团队、方案、资源、FAQ、联系方式 | /site-content |
| GET /api/v1/health | 服务健康及内容版本 | /healthz，以及生产 API 根路径 / |

新旧地址直接返回相同数据，不跳转。HEAD 支持状态和头部检查；产品和内容接口 OPTIONS 返回 204。写入方法返回 405，并带 Allow。

成功：

```json
{"data": [], "meta": {"version": "16位内容哈希", "apiVersion": "v1"}}
```

产品的 `data` 为数组，站点内容为对象，完整字段见 `docs/api-examples/`。示例使用源文件的相对图片路径；真实 API 根据 `PUBLIC_ASSET_BASE` 或快照 `assetBase` 转为绝对 HTTPS 地址，本机联调允许 HTTP 回环地址。

字段校验同时位于 `backend/validation.py` 与 `site/assets/js/content-contract.js`。ID 只能小写英文、数字和短横线，组内唯一；图片、链接限定为允许的地址；必需字段不得缺失。合法空产品数组和空联系人数组有效。`status` 是平台信息扩展字段，不是公开状态开关，草稿不得进入公开内容文件。

接口快照来自 `content/products.json` 和 `content/site-content.json`，运行 `npm run sync` 生成；生成的版本在启动时复核。运行中两份内容固定在同一快照，更新后重新部署。两个响应的 `meta.version` 必须相等，并与网页 `CONTENT_VERSION` 相同，前端才启用 API 数据；失败会整体回退网页本地副本。

错误：

```json
{"error":{"code":"NOT_FOUND","message":"接口不存在","requestId":"请求编号"}}
```

404/405/500 为 JSON，500 不向访客返回堆栈；云平台自身错误不受应用控制。服务端日志与 `X-Request-ID` 可关联排查。

所有应用 JSON 响应使用 `application/json; charset=utf-8`。内容 GET：`Cache-Control: public, max-age=60, must-revalidate`、ETag，If-None-Match 命中返回 304；健康和错误：no-store。版本还在 `X-Content-Version` 中。

CORS 只回显 `ALLOWED_ORIGINS` 中的确切来源，`Vary: Origin`，不接受凭据。默认包括 GitHub Pages 来源和本机 4173/4174；生产建议仅保留 `https://lmh7.github.io`。来源是“协议+主机+端口”，不包含仓库路径。CORS 不限制直接访问公开 API，也不是身份认证。

前端从 `config/public.json` 切换数据源，生成的 `_headers` 会同步接口和图片来源。公网验收使用 `node scripts/backend-task.mjs smoke 根地址 --version 内容版本`，随后还须在实际网页检查浏览和图片。
