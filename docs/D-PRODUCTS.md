## 2 数据字段（`content/products.json`，前端由 `products.js` 读取）

| 字段 | 类型 | 必填 | 为空或缺失时的页面表现 |
| --- | --- | --- | --- |
| `id` | 字符串，`^[a-z0-9-]+$`，唯一 | 是 | 地址无效 → “未找到该产品” |
| `name` | 字符串 | 是 | — |
| `subtitle` | 字符串 | 建议 | 图区角标只显示 “NEX SERIES ·” |
| `sensor` | 字符串，与筛选按钮一致 | 是 | 标签为空，筛选无法命中 |
| `image` | 站内相对路径 | 是 | 换本地占位图 + “产品图待补充”说明 |
| `imageAlt` | 字符串 | 是 | 图片替代文字不完整 |
| `summary` | 30—60 字 | 是 | “产品简介待补充，建议 100—150 字。” |
| `description` | 100—150 字 | 是 | 同上 |
| `features` | `{title,text}[]`，建议 3 条 | 建议 | 一张“平台特点待补充”卡 |
| `specs` | `{label,value}[]` | 是 | 至少补“平台型号 / 传感器类型”两行 |
| `applications` | 字符串数组 | 是 | 方向区为空，不报错 |
| `applicationSolutions` | 方案 ID 数组，与 `applications` 同序 | 否 | 对应方向跳转方案总览 |
| `resources` | `{title,url}[]` | 是 | 4 张通向资源与支持的“资料待补充”卡 |
| `video` | 站内路径或空字符串 | 否 | 16:9 占位区，无播放按钮 |
| `contentStatus` | `placeholder` / `partial` / `complete` | 否 | 用于内容维护登记，不输出顶部提示条 |
| `status` | 字符串（旧字段，保留） | 否 | 无影响 |

三条硬规则：

1. **不编造**。没有确认的重量、续航、价格和文件，一律写“参数值待确认”或保持空数组。
2. **`resources[].url` 不能为空**，否则 `data-service.js` 的 `validateProducts` 会整体回退；没有资料就写 `[]`。
3. **新增传感器类型要两处同步**：`content/products.json` 的 `sensor`、`products.html` 的筛选按钮，再执行 `npm run sync`；`products-page.js` 无需改（筛选值从按钮读取）。

## 3 页面结构

### 3.1 产品列表 `products.html`

区块顺序：页面主视觉 → 系列标题 → 筛选按钮 + 搜索框 → 结果计数 → 卡片网格 → 零结果提示 → 对比条 → 说明与联系入口。

- 卡片由 `app.js` 统一渲染（与首页共用），`products-page.js` 只切换 `hidden`，不重复生成卡片。
- 计数格式固定为 `显示 X / Y 款平台`，容器带 `role="status" aria-live="polite"`。
- 筛选与关键词写入地址栏 `?sensor=`、`?q=`，刷新、分享、从缓存返回都能还原。
- 零结果时显示 `#products-empty`，可一键重置并聚焦搜索框；`Esc` 清空关键词，关键词已空时再按一次回到全部平台。

### 3.2 产品详情 `product.html`

`?id=` 取记录，区块顺序按规划 §3.2：

1. 工具条：面包屑 + 返回产品中心。
2. 主图（可放大）+ 型号、传感器、简介、正文、咨询、分享。
3. 平台特点（3 张卡）。
4. 平台参数（表，未确认值标灰）。
5. 探索研究方向。
6. 演示视频（16:9 预留位，无播放按钮）。
7. 文档与资料（4 个资料位或真实链接）。
8. 联系条 + 其他平台。

### 3.3 错误状态

| 输入 | 提示 | 其他处理 |
| --- | --- | --- |
| `product.html`（无 id） | “产品地址缺少产品编号（?id=），请从产品中心重新选择平台。” | 标题改“未找到产品”，`noindex, nofollow`，canonical 指向列表页 |
| `?id=missing` | 原样回显编号（已转义），提示可能已更新 | 同上，另给 3 个候选平台 |
| `?id=<script>…` | 转义后回显，不执行 | 候选链接用 `encodeURIComponent` |
| 图片 404 | 换占位图 + “产品图待补充”角标 | 只回退一次，用 `data-fallback="done"` 防循环 |

静态托管无法返回真实 404 状态码，因此错误页靠 `noindex` 避免被收录，返回入口保持可用。

## 4 与公共脚本的接口

| 依赖 | 提供方 | D 的用法 |
| --- | --- | --- |
| `#site-header` / `#site-footer` 容器 | `layout.js` | 保留空容器，不写死导航 |
| 数据就绪 | `data-service.js` | `await SiteData.ready`，读 `window.PRODUCTS` |
| 转义、图标、地址过滤 | `layout.js` 的 `UI.escape / icon / url` | 所有数据字段进模板前转义 |
| 图片放大弹窗 | `interactions.js` | `data-image-zoom` + `data-image-title` |
| 分享 | `interactions.js` | `data-share-product` |
| 对比 | `interactions.js` + `app.js` 渲染的复选框 | 筛选时自动取消被隐藏卡片的勾选，避免对比表出现看不见的平台 |
| 带型号咨询 | `app.js` | 链接写 `contact.html?product=<id>` |

**单一筛选控制器**：整合时已从 `app.js` 移除旧筛选块。
`products-page.js` 等待 `APP_READY` 完成卡片渲染后，直接绑定原有搜索、筛选与重置控件。
隐藏已勾选卡片时会触发复选框 change 事件，保证对比栏同步更新。

## 7 15 分钟替换演示

### 7.1 换一张产品图

1. 把新图按 4:3 裁好，存为 `site/assets/images/nex-500.webp`（覆盖同名文件时无需改代码）。
2. 若换文件名，改 `content/products.json` 中该记录的 `image` 与 `imageAlt`。
3. 执行 `npm run sync` 后刷新列表与详情，两处同时生效；图裂时会自动回退占位图。

### 7.2 改一段产品简介

1. 打开 `content/products.json`，改对应 `summary` 和 `description`。
2. 执行 `npm run sync` 后刷新：首页卡片、列表卡片、详情首屏三处同步变化，无需改 HTML。

### 7.3 新增一款产品

1. 在 `content/products.json` 复制一条记录，改 `id`（小写字母与连字符）、`name`、`sensor`，并核对 `applicationSolutions`。
2. 若有新的传感器类型，在 `products.html` 加一个 `data-product-filter="新类型"` 按钮。
3. 执行 `npm run sync`，首页、列表、详情、对比、全站搜索都会带上新记录。

### 7.4 启用真实资料

1. 把文件放到 `site/assets/docs/`（新建目录）或已有公开地址。
2. 在 `content/products.json` 对应记录的 `resources` 中写 `{ "title": "用户手册", "url": "assets/docs/nex-500-manual.pdf" }`，然后执行 `npm run sync`。
3. `url` 必须是站内相对路径或 `https://`，否则会被 `UI.url` 过滤，该项退回“资料待补充”。

```bash
git switch feat/about-navigation-c-20261109

```

- 交叉验收：F（检查数据字段、占位说明、错误状态文案）；合并：A；发布复查：G。
- 冲突高发：`products.html` 的 `<head>`（C 也可能加脚本）、`products.js`（首页 hero 字段）。
  合并前先 `git pull --ff-only`，冲突时保留两边新增，不要整文件覆盖。
- 回滚：`git revert <merge-sha>`；单文件回滚用 `git checkout <sha> -- <path>`。
